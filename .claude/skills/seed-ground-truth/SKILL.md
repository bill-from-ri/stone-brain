# Seeding a ground-truth document

Ground truth is the hand-read labelling of a document that extraction output is
**scored** against — today Gemini's, later any user-provided model's
(`docs/implementation-plan.md` Phase 2B). If the labels are sloppy, inconsistent
between documents, or generated by a model, the scoring measures nothing. Your job
is to produce labels that are **more correct and more disciplined than any
model's**, and identical in style to every other seeded document.

Read before starting:
- `examples/kaldian-empire-draft.md` (in this skill's folder) — the structural
  template for a draft, frozen as it stood at seeding. Its data is in
  `src/lib/ontology/seed-kaldia.ts`.
- `docs/ontology-design.md` → *Modelling conventions* (every settled modelling
  ruling) and *Deliberately not modelled* (out of scope — never proposed). Where
  the example and this disagree, this wins.
- `docs/deferred-proposals.md` — every ontology change already proposed and
  deferred. **Never propose one of these again** (see step 5).

## The five things that matter most

1. **The ontology is the source of truth, read it live.** Never label against a
   remembered vocabulary. `src/lib/ontology/registry.ts` is the single source for
   entity types, predicates, and their legal `(subject type → object type)`
   signatures. A claim whose signature is not in the registry is rejected by a
   database FK (`claims_signature_fk`) — the constraint layer, not a lint.
2. **Consistency beats coverage.** Two agents labelling two documents must make
   the *same* choices — naming, typing, quoting, reading-vs-inferred. Follow
   [Conventions](#conventions) exactly. A defensible 40 claims beat an aggressive 70.
3. **Ontology changes are ratified by a human, and serialized.** A document often
   argues for a new predicate or type. Propose it **in the draft** and stop for
   approval. Do **not** edit `registry.ts` on your own judgement, and — if several
   agents run in parallel — do not edit it concurrently: registry edits are a
   single serialization point (see [Parallel agents](#parallel-agents)).
4. **Quotes are verbatim substrings of the paragraph they cite.** A quote a reader
   cannot find in the document is a broken citation. Copy from `render-paras.ts`
   output and check every quote with `check-seed-quotes.ts` (step 9).
5. **Idempotent and reversible-by-design.** Seeding re-runs safely (entities match
   on `(user, type, normalized name)`, claims on `fingerprint`). Always `--dry`
   first, then seed, then verify.

## Running the helper scripts

Any script that imports `@/db` or `@/lib/env` (both are `server-only`) must run
with the `react-server` condition, or it crashes on import. That is every helper
below. The exact form:

```
npx tsx --conditions=react-server --tsconfig tsconfig.json scripts/<script>.ts <args>
```

| Script | Args | What it gives you |
| --- | --- | --- |
| `list-corpus.ts` | — | every document, its export size (a poor length proxy — images), and its citation count if already seeded |
| `dump-text.ts` | `<outDir> "<name>"...` | cleaned text to files, plus length stats |
| `render-paras.ts` | `"<name>"` | the document exactly as the extractor sees it, with `[¶n]` markers |
| `list-entities.ts` | `[filter]` | every existing entity by type, with variants and citing-document counts |
| `check-seed-quotes.ts` | `[seed ...]` | every seeded quote checked against its cited paragraph in the live document |

The `npm run db:seed*` scripts do **not** need the flag — they build their own
database client instead of importing `@/db`.

## Workflow

### 1. Choose the document (if not given one)
- Short-to-medium, **diverse** in entity types and predicate families. `sizeBytes`
  is a bad length proxy (mostly embedded images) — use `list-corpus.ts`.
- **Exclude** documents used to tune the extractor (*Village of Nephten*, *The
  Republic of Andras*) — scoring against tuning data is biased. Exclude documents
  already seeded (`list-corpus.ts` marks them).

### 2. Export and check citability
Run `render-paras.ts "<name>"`. Confirm the paragraphs are clean, citable units.
- **Layout-table documents** (a whole article in one Google-Docs table cell) are
  recovered by `splitLayoutTable`; if a document is only 1–2 paragraphs for
  thousands of characters, that recovery failed — flag it rather than label it.
- **A bulleted list is one paragraph.** Every item shares one `[¶n]`; that is by
  design (see `src/lib/drive/markdown.ts`).
- Bold and italic markers are stripped by the export cleaner, so quotes can run
  across emphasised words.

### 3. Read the whole document, the ontology, and the existing entities
Read every paragraph. Then read `registry.ts` in full — entity types, every
relationship's `pairs`, every attribute's `subjects`, enums, `temporal`/`functional`
flags. Your claims must use these exact predicate names and legal signatures.
Then run `list-entities.ts` and note every existing entity this document mentions:
you must reuse those spellings exactly (see [Conventions](#conventions)). Use its
filter to check near-clashes (`list-entities.ts enu` → Enua, Enuarak, …).

### 4. Catalog into a draft
Create `docs/seed-drafts/draft-seed-round-N.md`, where N is one more than the
highest round seeded so far (the Kaldian Empire was round 2, the Runar round 3).
Follow the structure of `examples/kaldian-empire-draft.md`, in this order: source
line, decisions, open questions, **Proposals**, then the catalog — entities grouped
by type with counts, proposed summaries, claims in a `¶ | claim | quote/note` table,
and a *Deliberately not claimed* list. Apply [Conventions](#conventions).

**The `## Proposals` section** holds every ontology change you propose, and nothing
else about the ontology. It is omitted when you have none — which should be common
(see step 5 for the bar). For each proposal, numbered `P1`, `P2`, …:

- **Change** — the type or predicate, its signatures, temporal or functional.
- **What would be lost without it** — the important information, in one sentence.
- **Evidence** — ¶ and verbatim quote for each supporting passage.
- **Reopens** — any past ruling it revisits (round and decision number), or "none".
- **Recommendation** — approve / defer / reject, with a one-line reason.
- **Conditional claims** — a `¶ | claim | quote` table of the claims it would
  unlock. They are **not** counted in the catalog totals. On approval they move into
  the main claims table; on deferral they go to `docs/deferred-proposals.md` in
  step 10, so the evidence outlives the draft.

End the section with a one-line-per-proposal summary table the user can rule from.

### 5. Propose ontology changes — sparingly — then STOP
**Propose a change only if it would capture important information that would
otherwise be lost.** Important means the information is central to what the
document is about, or a fact about the world someone would reasonably ask the graph
for — who rules, who fights whom, what a people practises, where something is. It
does not mean anything the vocabulary happens not to cover: an aside, a flourish, a
detail mentioned once in passing is tangential, and tangential information is not
worth changing the ontology for. "Otherwise lost" means no existing predicate or type
can hold it honestly; description that fits in an entity's `summary` is not lost.

Before proposing, check:
- **`docs/deferred-proposals.md`.** If the change is already there, do **not**
  propose it. If this document adds evidence for it, note that under open questions;
  in step 10 you append the evidence and any new conditional claims to that entry.
- **`docs/ontology-design.md` → *Deliberately not modelled*.** Out of scope; never
  propose these.
- **The registry.** A near-synonym that already exists is not a gap — use it.

Anything that fails the bar is not proposed: list it under *Deliberately not claimed*
with a few words on why. Never force a fact into a wrong predicate to avoid losing it.

Then present the proposals and open questions to the user and **stop** for rulings.
The user rules on each proposal individually: approve, defer, or reject.

### 6. Land ratified changes
Only after approval: edit `registry.ts` (add the pair/type/attribute), then
`npm run db:seed` to push the reference tables. Update the sizing comment in the
registry header and the counts in `docs/ontology-design.md`. Run
`npx vitest run src/lib/ontology/` and `npx tsc --noEmit`.

### 7. Duplicate check
Before writing the seed: scan for duplicate claims (same subject + predicate +
object/value + time) **within** the document and collapse an undated claim into its
dated twin. A claim that already exists from **another** document is kept: the
loader adds this document as a second source for it, which is correct — the fact is
stated in both, and an extractor reading this one should be credited for it.

### 8. Write the seed module
Create `src/lib/ontology/seed-<name>.ts` exporting `SEED_DOCUMENT_*`, `*_ENTITIES`,
`*_CLAIMS`, and a `seed<Name>()` that calls the shared `loadSeed()` from
`seed-world.ts` (do not re-implement the loader). Add `scripts/seed-<name>.ts`
(copy `scripts/seed-kaldia.ts`, which supports `--dry` and `--user=`), a
`db:seed:<name>` line in `package.json`, and an entry in `SEEDS` in
`scripts/check-seed-quotes.ts`. Get the document's `driveFileId` from the
`documents` table (`drive_file_id`).

### 9. Dry-run, seed, verify
- `npm run db:seed:<name> -- --dry` — sanity-check counts, dates→ordinals, inferred list.
- `npm run db:seed:<name> -- --user=<uuid>` — seed. `loadSeed` also marks the
  document **Verified** (a hand-seed is ground truth by definition).
- **Verify:**
  - `check-seed-quotes.ts <name>` — every quote found in its cited paragraph.
  - The run's `sources` count equals the number of *sourced* claims in the seed
    (every claim cited from this document, including ones that already existed;
    hand-entered claims have no source).
  - Re-run the seed: `0 created`, `0 citations written`.
  - Cross-document entities were reused, not duplicated (`list-entities.ts <name>`
    shows one row, citing 2+ documents).
  - Intended ambiguities resolve to multiple candidates (`resolveEntity` from
    `matcher.ts`).
  - `npx vitest run`.

### 10. Fold the draft back, then delete it
The draft is scratch space, not a design record. Once seeded and verified:
- Add each newly ratified modelling ruling to `docs/ontology-design.md` →
  *Modelling conventions*.
- Add each **deferred** proposal to `docs/deferred-proposals.md` as a new `D<n>`
  entry — proposed round and date, change, why deferred, evidence, and its
  conditional claims as *Parked claims*. Append new evidence to existing entries the
  same way. Check every quote you copy there against `render-paras.ts`.
- Move each **rejected** proposal to *Deliberately not modelled* in
  `ontology-design.md`.
- If an approved proposal was an existing `D<n>` entry, delete that entry once its
  change has landed and its parked claims are seeded.
- Update the entity-type list and vocabulary counts in `ontology-design.md` if the
  registry changed.
- Add any new labelling convention to [Conventions](#conventions) below.
- Delete `docs/seed-drafts/draft-seed-round-N.md`. The seed module carries the data;
  git history keeps the reasoning.

## Conventions

**Names**
- **The document's fullest form, minus titles.** `Lukas Kalduin`, not `Prince Lukas
  Kalduin` (the title is a separate claim). Resolve pronouns and epithets to the name.
- **No leading "The"** — in names and in variants. `Doom`, `Dragon's Shroud`,
  `Interior`, `Pale War`, `Empire`. The matcher already treats "the Doom" and "Doom"
  as the same name, so nothing is lost.
- **Title case for every name**, commodities included: `Grain`, `Monster Parts`,
  `Kaldian Culture`, `Runar Religion`.
- **Peoples are plural**: `Tvars`, `Atarks`, `Conservatives`. A singular form the
  document uses goes in `variants` (`Tvar`).
- **Only a proper name makes an entity.** "The deep inland forest", "Steppe peoples to
  the east", "a period of civil war" are descriptions — leave them out and note them under
  *Deliberately not claimed*.
- **Cross-document reuse:** if an entity already exists (check `list-entities.ts`),
  name it **identically** — `normalizeName` folds case, diacritics, and punctuation,
  but the rest of the string must match for the loader to reuse the row.
- **`variants`:** alternate names go on the entity as `variants`, not as claims. A
  variant that is also its own entity is allowed and deliberate — it makes
  `resolveEntity` return two candidates (the matcher's ambiguous path).

**Types**
- Pick the registry type whose description fits, and check *Modelling conventions*
  in `docs/ontology-design.md` for the settled cases. The recurring ones:
  - Dynasties and houses → `faction`. Political alliances within a state → `faction`
    `member_of` the society.
  - Any people considered as a whole → `society`, **whether or not it is a state** —
    a tribe with no government is still a `society`. The test: a group that acts as a
    unit (wars, trades, migrates, is ruled) is a `society`; a shared way of life across
    groups is a `culture`, linked by `practices`. A people and its polity may have
    different names — the Enu (culture), Enuarak (society).
  - Sub-polities (a duchy within an empire) → `society`, `serves` the parent.
  - Land features → `region`; the enums `climate` (biome) and `landform`
    (geomorphology) are independent.
  - Kinds of living being → `species`, named in the singular (`Dragon`, `Tvarid
    Spruce`); a named individual → `character`, linked by `of_species`.
- **Political control of a region → `rules`** (a region cannot be `located_in` a
  society). Geographic containment or habitation → `located_in`.

**Summaries**
- **Every new entity gets a `summary`**: one or two sentences, drawn from the
  document, saying what the entity is. It is the entity's only description — there is
  no `description` claim — and it is what the entity's detail card shows. Prose no
  predicate can hold (a byname, a purpose, a comparative) belongs here.
- A summary already on an existing entity is never overwritten by a seed; the loader
  only fills one that is missing.

**Quotes and inference**
- **Quotes:** verbatim substring of the cited paragraph, copied from
  `render-paras.ts`. Documents mix curly (`’`) and straight (`'`) apostrophes, even
  within one paragraph — copy, never retype. `paragraph` is the `[¶n]` index.
- **Hand-entered claims:** a link the user rules true but no single document states
  (Enuarak `located_in` Enua) goes in the seed with `handEntered: '<why>'` and no
  quote. It is written as `created_by: 'user'` with no citation, so it is never part
  of any document's ground truth. Only on the user's ruling — never your own.
- **`inferred`:** set it on any claim that is a reading rather than a direct quote,
  with a one-line reason. If a claim needs a predicate the vocabulary lacks, drop it
  and log the gap — never substitute a near-synonym.

**Dates**
- Copy the label verbatim; ordinals are derived — never hand-compute them.
- **A year with no era is AD**, unless the document's context clearly says otherwise.
  If it is ambiguous, it is AD.
- `startTime`/`endTime` only when the document states a period, and **only on
  temporal predicates** (the `temporal` flag in `registry.ts`). `located_in` and other
  non-temporal predicates carry no dates.

## Parallel agents

When several agents seed different documents at once:
- **One agent owns `registry.ts` at a time.** Collect all proposals, have the human
  ratify the union, land the changes and `npm run db:seed` **once**, then let agents
  write their seed modules. Concurrent registry edits conflict and concurrent
  `db:seed` runs race.
- `docs/deferred-proposals.md` is shared too: the same owner appends to it in step 10.
- Seed modules and draft files are per-document and don't collide. `loadSeed` is
  concurrency-safe at the row level (idempotent upserts), but give each document its
  own `driveFileId` and normalized-name space; cross-document reuse is a feature, not
  a conflict.

## Gotchas

- **Drive auth expires** (7-day testing-mode refresh token). `invalid_grant` on export
  means re-link Google in the app; nothing here can fix it headlessly.
- **`--user=<uuid>`** is required to seed; get it from the `users` table.
- **Don't run throwaway scripts from `/tmp`** — tsx's module resolution breaks there.
  Put them in `scripts/` (prefixed `_`) and delete them when done.
- **`npx tsx -e '…'` hangs** on this project's top-level-await imports. Write a
  throwaway script file instead.
