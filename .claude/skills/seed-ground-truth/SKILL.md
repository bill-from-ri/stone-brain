# Seeding a ground-truth document

Ground truth is the hand-read labelling of a document that extraction output is
**scored** against — today Gemini's, later any user-provided model's
(`docs/implementation-plan.md` Phase 2B). If the labels are sloppy, inconsistent
between documents, or generated by a model, the scoring measures nothing. Your job is to produce labels that are **more
correct and more disciplined than any model's**, and identical in style to every
other seeded document.

Two worked examples exist — read them before starting; they are the spec:
- `docs/seed-drafts/draft-seed-round-1.md` + `src/lib/ontology/seed-world.ts` — *Written Map*, geography.
- `examples/kaldian-empire-draft.md` (in this skill's folder) + `src/lib/ontology/seed-kaldia.ts` — *The Kaldian Empire*, people/politics. The richer template, frozen as it stood at seeding.

Settled modelling rulings from past rounds are in `docs/ontology-design.md` → *Modelling conventions*; read that too.

## The five things that matter most

1. **The ontology is the source of truth, read it live.** Never label against a
   remembered vocabulary. `src/lib/ontology/registry.ts` is the single source for
   entity types, predicates, and their legal `(subject type → object type)`
   signatures. A claim whose signature is not in the registry is rejected by a
   database FK (`claims_signature_fk`) — the constraint layer, not a lint.
2. **Consistency beats coverage.** Two agents labelling two documents must make
   the *same* choices — naming, typing, quoting, reading-vs-inferred. Follow
   [Conventions](#conventions) exactly. A defensible 40 claims beat an aggressive 70.
3. **Ontology changes are ratified by a human, and serialized.** A document often
   argues for a new predicate or type. Propose it **in the draft** and stop for
   approval. Do **not** edit `registry.ts` on your own judgement, and — if several
   agents run in parallel — do not edit it concurrently: registry edits are a
   single serialization point (see [Parallel agents](#parallel-agents)).
4. **Quotes are verbatim substrings of the paragraph they cite.** A quote a reader
   cannot find in the document is a broken citation. Copy from the rendered
   paragraph text, and prefer substrings without curly apostrophes (`’`) to avoid
   mismatch.
5. **Idempotent and reversible-by-design.** Seeding re-runs safely (entities match
   on `(user, type, normalized name)`, claims on `fingerprint`). Always `--dry`
   first, then seed, then verify.

## Workflow

### 1. Choose the document (if not given one)
- Short-to-medium, **diverse** in entity types and predicate families. `sizeBytes`
  is a bad length proxy (mostly embedded images) — use the helpers below.
- **Exclude** documents used to tune the extractor (*Village of Nephten*, *The
  Republic of Andras*) — scoring against tuning data is biased. Exclude already-seeded
  documents (query `claim_sources` grouped by `document_id`; *Written Map* and *The
  Kaldian Empire* are done).
- Helpers (read-only, no LLM): `scripts/list-corpus.ts` (corpus + which are seeded),
  `scripts/dump-text.ts <outDir> "<name>"...` (cleaned text + length),
  `scripts/render-paras.ts "<name>"` (paragraphs with `[¶n]` markers).

### 2. Export and check citability
Run `render-paras.ts`. Confirm the paragraphs are clean, citable units. **Layout-table
documents** (a whole article in one Google-Docs table cell) are recovered by
`splitLayoutTable`; if a document is only 1–2 paragraphs for thousands of characters,
that recovery failed and the document is not labellable as-is — flag it.

### 3. Read the whole document, then read the ontology
Read every paragraph. Then read `registry.ts` in full — entity types, every
relationship's `pairs`, every attribute's `subjects`, enums, `temporal`/`functional`
flags. Your claims must use these exact predicate names and legal signatures.

### 4. Catalog into a draft
Create `docs/seed-drafts/draft-seed-round-N.md`, following the structure of `examples/kaldian-empire-draft.md`:
source line, decisions, open questions, ontology-change sections, a registry-changes
table, then the catalog (entities grouped by type with counts; claims in a `¶ | claim
| quote/note` table; a "deliberately not claimed" list). Apply [Conventions](#conventions).

### 5. Propose ontology changes — then STOP
List every proposed registry change with its evidence. **Present them to the user
and wait for ratification.** Only spurious inference should be dropped; real facts
the vocabulary can't express are logged as gaps, not forced into wrong predicates.

### 6. Land ratified changes
Only after approval: edit `registry.ts` (add the pair/type/attribute), then
`npm run db:seed` to push the reference tables. Update the sizing comment in the
registry header. Run `npx vitest run src/lib/ontology/` and `npx tsc --noEmit`.

### 7. Duplicate check
Before writing the seed: scan for duplicate claims (same subject+predicate+object/value+time)
within the document and against already-seeded entities. Collapse an undated claim into
its dated twin. Reuse existing entities by their exact name (see conventions).

### 8. Write the seed module
Create `src/lib/ontology/seed-<name>.ts` exporting `SEED_DOCUMENT_*`, `*_ENTITIES`,
`*_CLAIMS`, and a `seed<Name>()` that calls the shared `loadSeed()` from
`seed-world.ts` (do not re-implement the loader). Add `scripts/seed-<name>.ts`
(copy `scripts/seed-kaldia.ts`, which supports `--dry` and `--user=`) and a
`db:seed:<name>` line in `package.json`. Get the document's `driveFileId` from the
`documents` table.

### 9. Dry-run, seed, verify
- `npm run db:seed:<name> -- --dry` — sanity-check counts, dates→ordinals, inferred list.
- `npm run db:seed:<name> -- --user=<uuid>` — seed. `loadSeed` also marks the
  document **Verified** (a hand-seed is ground truth by definition).
- **Verify:** re-run to confirm idempotency (0 created); confirm `claim_sources`
  count equals claim count; confirm any cross-document entities are reused not
  duplicated; confirm intended ambiguities resolve to multiple candidates
  (`resolveEntity` from `matcher.ts`). Run `npx vitest run`.

### 10. Fold the draft back, then delete it
The draft is scratch space, not a design record. Once seeded and verified:
- Add each newly ratified modelling ruling to `docs/ontology-design.md` →
  *Modelling conventions*, and each deferred item to *Deferred vocabulary*.
- Update the entity-type list and vocabulary counts in `ontology-design.md` if the
  registry changed.
- Delete `docs/seed-drafts/draft-seed-round-N.md`. The seed module carries the data;
  git history keeps the reasoning.

## Conventions

- **Entity names:** the document's fullest form, minus titles. `Lukas Kalduin`, not
  `Prince Lukas Kalduin` (title is a separate claim). Resolve pronouns/epithets to the name.
- **Cross-document reuse:** if an entity already exists (e.g. `Elduin`, `Grain`),
  name it **identically** — `normalizeName` folds case/diacritics/punctuation but does
  **not** strip articles, so the string must match for the loader to reuse the row.
- **`variants`:** alternate names go on the entity as `variants`, not as claims. A
  variant that is also its own entity is allowed and deliberate — it makes
  `resolveEntity` return two candidates (the matcher's ambiguous path).
- **Types:** pick the registry type whose description fits. Dynasties/houses →
  `faction`. Sub-polities (a duchy within an empire) → `society`. Land features →
  `region`; enums `climate` (biome) and `landform` (geomorphology) are independent.
- **Political control of a region → `rules`** (a region cannot be `located_in` a
  society). Geographic containment → `located_in`.
- **Quotes:** verbatim substring of the cited paragraph; prefer apostrophe-free spans.
  `paragraph` is the `[¶n]` index from `render-paras.ts`.
- **`inferred`:** set it on any claim that is a reading rather than a direct quote, with
  a one-line reason. If a claim needs a predicate the vocabulary lacks, drop it and log
  the gap — never substitute a near-synonym.
- **Dates:** copy the label verbatim; bare years default to AD. `startTime`/`endTime`
  only when the document states a period. Ordinals are derived — do not hand-compute.

## Parallel agents

When several agents seed different documents at once:
- **One agent owns `registry.ts` at a time.** Collect all proposals, have the human
  ratify the union, land the changes and `npm run db:seed` **once**, then let agents
  write their seed modules. Concurrent registry edits conflict and concurrent
  `db:seed` runs race.
- Seed modules and draft files are per-document and don't collide. `loadSeed` is
  concurrency-safe at the row level (idempotent upserts), but give each document its
  own `driveFileId` and normalized-name space; cross-document reuse is a feature, not
  a conflict.

## Gotchas

- **Drive auth expires** (7-day testing-mode refresh token). `invalid_grant` on export
  means re-link Google in the app; nothing here can fix it headlessly.
- **`--user=<uuid>`** is required to seed; get it from the `users` table.
- **`react-server` condition:** scripts that import `server-only` modules (Drive,
  provider) need `npx tsx --conditions=react-server`; the `db:seed:*` npm scripts that
  only touch the DB do not.
- **Don't run throwaway scripts from `/tmp`** — tsx's module resolution breaks there.
  Put them in `scripts/`.
